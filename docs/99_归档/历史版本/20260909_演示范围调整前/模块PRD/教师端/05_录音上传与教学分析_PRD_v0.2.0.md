# 教师端｜录音上传与教学分析 PRD v0.2.0

## 1. 产品定义

- **这是什么功能：** 上传教师教学录音，经转写与AI分析获得教学多维结论和证据。
- **帮助用户解决什么问题：** 让既有讲课录音无需重新授课即可进入分析流程。
- **为平台带来什么价值：** 为教师能力画像提供可回看的教学证据。

> **实施前置依赖：** 转写服务尚未确认，需文件格式、限制、告知与保存规则；DeepSeek文本接口不替代ASR。D-F03、D-F04。 统一见[实施依赖清单](../../实施依赖与待确认清单.md)。已确认产品行为不等于服务已接通或医学效果已验证。

## 2. 产品结构

记录列表 → 上传录音 → 转写及校订 → AI分析 → 证据回看。

共用阶段、数据版本与权限原则见[需求总纲](../../独立病理教学网站MVP需求稿_v0.1.0.md)，模块入口见[目录](../README.md)。

## 3. 核心流程与功能需求

| 编号 | 能力 | 截图示意说明 | 文字说明 |
|---|---|---|---|
| T-AUDIO-01 | 上传教学录音 | 主题、可选病例关联、文件选择及进度 | 使用已有录音文件，不以站内实时麦克风采集为第一期前提。确认素材使用权限及内容范围，展示文件类型、大小／时长限制；失败保留表单可重试。 |
| T-AUDIO-02 | 生成转写 | 播放器、带时间戳文本及处理状态 | 上传成功后转写，不以文件上传完成冒充分析完成。保留实际时长、原音频及转写版本；听不清和说话者不明明确标记，不凭声纹猜身份。 |
| T-AUDIO-03 | 校订与分析 | 可修改转写、原文对照及分析按钮 | 教师可校订术语和角色归属后发起分析；原转写不覆盖，重新分析引用新版本。分析引用音频时间片段及已授权病例依据。 |
| T-AUDIO-04 | 分析互动问答 | 问题、回应、追问及时间戳证据 | 识别实际问答及教学策略；无互动显示未识别到有效问答，不伪造学生提问，不用问答数量直接评价优劣。 |
| T-AUDIO-05 | 分析诊断一致性 | 讲解判断、参考资料及差异 | 按讲解内容与已确认病例资料比较，保留合理诊断修正；未关联病例或参考不足时只整理表达、不输出医学正确率。 |
| T-AUDIO-06 | 分析讲解轨迹 | 讲解顺序与可用视野证据 | 音频可支持讲解主题顺序，不提供图片操作坐标。没有真实阅片事件时，图像轨迹分析显示缺少轨迹数据，不伪造热图或同步移动视野。 |
| T-AUDIO-07 | 查看多维结论 | 结论摘要、证据引用、限制和回放 | 音频优先支撑专业知识、教学技能相关证据；AI应用与资源建设需额外实际记录。点击引用跳到音频对应时间，不能用相似文本冒充音画同步。 |

## 4. 专项规则与数据关系

已确认从旧“录音仅示例UI”升级为上传录音分析的目标需求；本次只改文档，真实转写接入仍是实施依赖。三类分析独立成功／失败；文件与任务版本固定，校订后旧结果标旧版本。未提供轨迹不阻断音频可以完成的分析。

所有保存反馈必须对应实际写入结果；本机保存不显示已同步云端。修改被引用内容建立新版本，历史记录使用当次快照。未落实医学规则不由开发者或模型自行定为标准。

## 5. 权限与状态

默认教师本人录音和授权病例；查看他人录音须明确授权。状态：待上传／上传中／失败／待转写／转写中／待校订／分析中／完成／部分失败／依据不足。录音、转写和结论不公开给学生。

真实服务接入时同时校验入口、列表、检索、详情、文件和写入；浏览器演示不能声称具备真实隔离。

## 6. 界面框架

列表主操作上传录音；详情左播放器与转写，中／右分析标签及证据卡。多维摘要先展示，点击再深入；不显示无证据的轨迹动画。

沿用六院绿色Design System与旧平台相关组件；截图示意说明是页面设计要求，不是本轮已完成截图。参考学生旧稿[第10节界面框架](../../../03_Agent方案/切入点需求稿/07_切片图书馆病例模拟作答/学生病理教学模块需求稿_v0.3.1.md#10-界面框架)，仅继承适用布局，不恢复已取消的多选、复杂简答表格及强制标注规则。
