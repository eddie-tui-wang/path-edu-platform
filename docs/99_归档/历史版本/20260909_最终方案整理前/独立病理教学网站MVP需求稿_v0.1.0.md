## 1. 产品定义

- **这是什么功能：** 面向六院教师和病理学生的独立教学网站，第一期用 JPG／PNG 和浏览器本地数据承载完整教学流程原型；真实服务分步接入，第二期扩展真实 WSI。
- **帮助用户解决什么问题：** 让教师在院外完成病例准备、考试组织和教学过程分析，让学生完成临床信息阅读、图片观察、作答标注和结果复习。
- **为平台带来什么价值：** 在独立账号与数据权限下沉淀病例、答卷、教学证据和师生能力记录，形成可验证、可追溯、可持续升级的教学 MVP。

> **实施前置依赖：** 专家参考答案、评分规则、四维／五维指标及有效数据量，模型与转写服务、素材授权、录音告知、部署资源均须按[依赖清单](./实施依赖与待确认清单.md)落实。已确认的是产品行为，不代表医学效果已验证或云服务已开通。规则未确认时展示证据和“规则待确认”，不得生成权威能力分数。依赖落实后更新 F04、F05、F15—F18、F21—F25 的规则版本及对应测试。

## 2. 建设边界与五层设计

| 考量 | 当前实施基线 |
|---|---|
| 战略层 | 独立医院教学网站，先服务六院单机构试用、20 人并发。可在院外访问；不等于患者资料可无条件外传。收费方式和跨机构商业模式未确定，不建设收费功能。 |
| 范围层 | 标准库、院方库、考试、我的学习、教师教学分析、必要管理后台。当前一期为本地流程原型，账号为公开演示身份、数据仅当前浏览器保存；真实账号服务保留独立入口，AI 不得伪装已接通。第一期不做 WSI、PACS／HIS／科研平台实时对接、自动病灶识别、课程／班级体系、排名、证书、错题重答或多机构协作。 |
| 结构层 | 数据库；考试中心；我的学习（考试记录／错题集／能力分析）；教师工作区（病例与标准资料／考试管理／教学记录／能力总览）；管理后台。入口按角色和授权展示，同一病例在不同场景使用不同可见字段。 |
| 框架层 | 学生三栏阅片作答；教师阅片时开始／结束记录，结束后分析；后台表单与列表完成维护。保存、上传和分析局部刷新，不丢失当前输入。详情保留返回来源及筛选条件。 |
| 表现层 | 沿用现有六院院徽与绿色 Design System、语义色、卡片、抽屉和表格；正文以 16px、辅助说明不小于 14px 作为第一期设计基线。窄屏折叠面板而非整体缩小，支持浏览器 200% 缩放，状态同时用文字表达。 |

两期优先顺序：第一期 P0 完成图片业务闭环；第二期 WSI 后续实施，未开工。独立代码仓库、账号、数据库、私有文件空间和部署配置不得与旧原型混用。独立项目已建立；本轮信息架构改造已在独立项目本地实施，不涉及推送或部署。

## 4. 角色与数据权限

| 角色／授权 | 可执行操作 | 数据边界与禁止项 |
|---|---|---|
| 学生 | 浏览开放库、参加分配考试、查看本人已发布成绩／错题／画像 | 不上传病例、不修改规则、不查看他人记录或未发布答案。 |
| 教师 | 维护授权院方病例及参考资料；管理授权考试、复核发布；采集本人教学并查看本人分析 | 不是机构内全部病例、学生或教师数据的默认查看者；标准库维护需要额外权限。学生画像仅限明确授权对象且仅聚合授权考试，不包含其他考试记录。 |
| 机构管理员 | 建立账号、授权病例／考试、维护任务与审计 | 机构边界内；不因管理员角色自动获得教师画像、录音、参考答案或所有答卷内容权限。需明确授予相应内容管理权限。 |
| 标准库维护权限 | 维护标准病例及发布范围 | 属独立功能权限，不因普通教师身份自动获得；第一期配置给指定负责人。 |
| 教师画像管理权限 | 查看明确授权教师画像及对应证据 | 单独指定对象与用途；不提供排行榜或自动奖惩。 |
| 技术运维权限 | 查看脱敏日志、任务状态、用量并重试异常 | 默认不能读取教学正文、音频或画像；不得更改分数。 |

服务端统一校验登录、角色、机构、资源范围、记录归属及结果发布状态；列表、搜索、详情、文件访问和后台任务均受约束。机构 ID 与用户 ID 由可信会话取得，不能信任浏览器提交的归属值。组合角色不自动扩大画像权限。撤权后终止后续访问并清理页面缓存，历史记录仍保留；资源本身失去授权时证据位置显示不可访问，不泄露内容。

## 5. 作答、评分与状态规则

### 5.1 第一期开发表现默认值

下列为本稿的实施默认值，用于避免开发者自行决定；不是专家医学评分标准。业务方若调整，应先更新文档及测试。

- 全选择题卷含单选和／或多选；全简答卷仅含简答；混合卷必须同时含选择和简答。
- 单选完全匹配得该题分值；多选选项集合完全匹配得分，否则零分。少选部分得分不在首期默认规则内。
- 简答按逐条评分要点分值累计；整卷为题目得分之和，不另叠加隐藏题型权重。发布前各要点合计必须等于该题分值。
- 第一期开考每人每场一份答卷，不提供重考。成绩由教师整场手动发布，避免先完成者泄露标准答案。
- 未答题记零分；有答案但分析失败不记零分，保持待分析／复核。依据不足的答案不得直接判错。
- 区域几何相似度只是证据，不能直接等于形态准确性；是否计分及阈值由专家规则决定。
- 题目可映射多能力维度，但每题对各维度的分值分配必须显式定义；没有映射只计考试分，不进入能力分。
- 规则升级不自动覆盖历史成绩。显式重新分析形成新版本；更正发布后更新有效错题及画像，旧分析仍可审计。

### 5.2 独立状态

| 对象 | 状态及约束 |
|---|---|
| 图片 | 上传中 → 校验／处理 → 可用；失败可重试。只有可用版本可发布到考试。 |
| 试卷／考试 | 草稿 → 已发布 → 开放／关闭；取消保留记录。与个人作答状态分开。 |
| 答卷 | 未开始 → 进行中 → 已提交；超时触发服务端提交，不允许恢复已提交答案。 |
| 分析 | 等待 → 执行中 → 完成／部分失败／失败／依据不足；依据不足不是成功评分，也不是服务故障。 |
| 成绩 | 待评分 → 待复核 → 待发布 → 已发布；更正形成新版本。 |
| 教学 | 记录中 → 待转写 → 可校订／分析中 → 完成／部分失败；中断和缺失片段单独标识。 |
| 画像 | 数据不足／规则待确认／更新中／可用；各维度分别显示覆盖量及有效记录范围。 |

## 6. 图片与数据接口约束

接口按能力定义，不在本稿锁定具体 HTTP 路径或云厂商 SDK。详细最小数据契约见[演进清单](./教学原型迁移与两期演进清单_v0.1.0.md)。

| 能力接口 | 输入 | 输出及约束 |
|---|---|---|
| 上传／影像读取 | 授权病例、文件信息；读取时指定影像版本 | 上传凭证、状态、尺寸、影像类型、可用能力及临时访问地址；不能返回公开永久存储地址。 |
| 答卷保存／提交 | 答卷、题目、答案、标注、预期修订号／提交标识 | 服务器修订号和时间、提交结果；冲突明确返回，不静默覆盖；提交幂等。 |
| 教学采集 | 教学记录、片段序号、相对时间、图片事件 | 接收确认、缺失片段、合并状态；刷新后使用同一记录，不伪造无录音时段。 |
| 分析／结果 | 固定输入版本、能力类型；读取时校验对象权限 | 任务状态、逐项结果、来源引用、模型和规则版本；学生结果接口额外受发布门禁控制。 |

临床资料、学生答案、教师原文、AI 建议、教师复核及最终发布结果分别保存。开发不能把模型输出直接覆盖原答或把病例显示标题作为参考诊断。

## 8. 当前实施基线与修订关系

当前为2026-09-09模块化基线v0.3.0：本文件维护公共规则，模块稿维护详细流程。原v0.1.0、v0.2.0及v0.2.1已归档，沿用主文件名保持链接稳定。当前文档交付范围见第9节，不把上轮布局验收等同新增业务闭环完成。

| 原规则 | 当前一期要求 | 后续真实服务要求 |
|---|---|---|
| F01—F02 服务端账号与授权 | 公开演示身份、角色入口、本地数据；同浏览器切换师生验证流程，不宣称安全隔离 | 真实账号入口与服务端机构／资源校验保留；无数据库时不能自动降级 |
| F03／F12 文件和答案服务端保存 | 本地导入与保存，明确容量、保存失败和清理数据后丢失；不得显示“已同步云端” | 私有文件存储、服务端版本和冲突恢复 |
| F14／F20 AI | 当前未接通；固定内容标为示例，不充当本人分析结果。是否本轮接入不作为布局实现前提 | 密钥服务端保管；按依赖清单落实调用、规则和来源 |
| F19／F21／F24 真实录音、转写、同步回放 | 仅演示 UI；不得新增人工录入替代业务，不索取麦克风 | 服务和采集方案落实后再开发 |
| F26 WSI | 不实施 | 保留第二期兼容约束 |

第3—6节保留目标业务规则；凡涉及真实基础设施，以本节阶段边界解释。完整流程原型不等于现有代码已经完成：阅卷、真实作答联动、成绩衍生记录仍待开发。20人并发、200%缩放、移动端及真实权限的验收不能以本次桌面浏览代替。
