## 1. 环境与验证手段

**Playwright 1.62.1 已经可用，不需要安装、也不要写进项目依赖。**

- 位置：`商汤医疗/node_modules/playwright`（注意在**工作区上一级**），本仓库直接 `import 'playwright'` 即可解析。
- 脚本用 `channel:'chrome'` 调**系统 Chrome**，无需下载浏览器二进制。
- `package.json` 里**没有**测试依赖，这是刻意的（AGENTS.md：不引入不必要的新依赖）。

跑法：

`sh
pnpm dev                                        # 终端 A：http://localhost:3002
node scripts/verify-<name>-browser.mjs          # 终端 B
`

**验收宽度：1440px 桌面。** 本平台面向医院教学工作站，**不做移动端／小屏适配**，768／390px 与 **200% 缩放均已退出验收项**（D-49）。脚本里仍有四档宽度循环，属**未清理的历史口径**，不代表仍需满足。

`NATIVE_ZOOM=200` 仍可运行，但不再是验收要求。

## 5. 给下一位的提醒

- **不要依赖聊天记录**。代码、测试与 `docs/` 才是事实来源。
- 医学内容一律**不要伪造**：AI、录音未接入；能力分析是**示例结论**（D-51），但维度下列出的证据是真实的。界面上的「示例」标注是**有意保留**的真实状态标识，不要当成冗余文案删掉。
- **验收宽度是 1440px 桌面**，不要为移动端做适配或加回窄屏分支（D-49）。
- 演示数据只在当前浏览器 localStorage 里，`pnpm start`（生产模式）**不支持 PGlite**，要体验账号必须用 `pnpm dev`。
- 修改前先确认改的是演示层还是真实账号层（见 [项目状态](./项目状态.md) §3），两者证据标准不同。
- 改文档后跑链接检查：`node ~/.dsh/skills/project-takeover/scripts/check-doc-links.mjs . --skip-archive`
- 保持独立项目边界：不要动旧科研平台。
- 本项目的接管方法论已沉淀为可复用 skill **`project-takeover`**（`~/.dsh/skills/`）。
- **采集脚本退出码别写成 `node x | tail -4; echo $?`**——那取到的是 `tail` 的退出码，会把失败记成通过。本轮就这样造出过一次假绿（见 §12.8）。
- 若 `localhost:3002` 无响应而 `lsof -nP -iTCP:3002` 仍有 LISTEN，是 dev server 卡死：**SIGTERM 无效，需 `kill -9`** 后以受管后台任务重启（见 §12.3）。
