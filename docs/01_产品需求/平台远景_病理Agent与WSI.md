# 病理教学平台产品需求稿 v1.0.0

## 1. 产品定义

- **这是什么功能：** 以病理 Agent 为统一入口、以数字切片病例训练为核心的教学模块，支持老师组织分部位训练、布置阅片和考核任务，并向学员提供练习、评分与反馈。
- **帮助用户解决什么问题：** 减少带教老师筛选病例、组题、逐份检查和统计学员表现的重复工作，让住培、进修及低年资病理医生获得持续、可追踪的阅片训练。
- **为平台带来什么价值：** 复用数智化平台的病例、数字切片、阅片器和 AI 结果，以及科研平台的标注、模型和评测能力，沉淀教学病例、专家金标准、题目、能力记录和错题等长期资产。

> **实施前置依赖：** V1 所需教学角色、学员档案、教学病例授权、病例脱敏、专家金标准、评分规则和教学任务状态尚未在现有两平台信息架构中得到确认。数智化平台的模型结果只能用于教学预分析，不能直接作为正式答案；教学病例、病灶区域、诊断要点和评分标准必须由有资质的病理专家审核并形成带版本号的教学金标准。相关接口和规则确认后，需要同步修订 F3—F15 及十项典型任务中的调用和评分描述。

## 2. 教学模块介绍

病理教学平台不是独立于临床和科研资产之外重新建设的一套课程网站。V1 的核心是把三类已有或可复用能力连接成一个教学闭环：

```text
老师提出教学目标
→ Agent 匹配部位、病种、职级和难度
→ 从已授权病例库组织教学病例
→ 调用数字阅片器完成真实病例练习
→ 基于专家金标准进行客观评分
→ Agent 生成错误解释和下一轮练习建议
→ 老师复核反馈并查看学员能力变化
```

教学内容从基础到复杂逐级展开：

1. 理论与图像选择题；
2. 典型视野识别题；
3. 病灶定位和分类题；
4. 癌区圈定与 Dice 评分题；
5. 鉴别诊断、免疫组化选择和结构化报告题；
6. 限时综合病例与阶段考核。

V1 主要服务病理住培医生、进修医生和低年资病理医生，带教老师、教学秘书和科主任负责组织、审核与评价。医学生课程管理、技师岗位授权、继续医学教育学分、院级教务排课和证书管理暂不纳入首版。

## 3. V1 教学场景

| 场景 | 触发方式 | 主要参与者 | 主要输出 |
|---|---|---|---|
| 入科摸底 | 老师创建入科任务，或学员向 Agent 发起“开始入科测试” | 学员、带教老师 | 基线成绩、能力画像、训练建议 |
| 分部位专项训练 | 老师指定胃肠、乳腺、肺等部位，或学员主动申请练习 | 学员、带教老师 | 分层病例包、练习记录、专项表现 |
| 日常数字阅片练习 | Agent 根据轮转计划、历史表现或老师布置推荐病例 | 学员 | 定位、圈定、诊断和报告结果 |
| 错题与薄弱点强化 | 学员提交练习后，由错误类型和能力缺口触发 | 学员、带教老师 | 错误解释、相似病例、复训任务 |
| 教学阅片与病例讨论 | 老师创建读片会或病例讨论任务 | 多名学员、带教老师 | 盲阅结果、分歧统计、讲评材料 |
| 阶段与出科考核 | 教学计划到期或老师主动创建考核 | 学员、考官、教学秘书 | 考核记录、评分草稿、人工确认结论 |
| 教学运营管理 | 老师或教学秘书查看班级、个人和病种完成情况 | 带教老师、教学秘书、科主任 | 完成率、薄弱点、逾期和干预名单 |
| 教学病例建设 | 老师从临床或科研资产中选择候选病例 | 病理专家、病例管理员 | 脱敏病例、金标准和版本记录 |

## 4. 核心流程与功能需求

| F2 | 明确教学目标 | **图2：教学目标确认卡。** 展示对象、部位、病种、能力项、难度、病例数和截止时间。 | Agent从用户请求中提取教学对象、目标和约束。信息不足时逐项补充，不直接创建任务；老师确认后形成结构化教学目标。 |

| F5 | 校验教学金标准 | **图5：金标准检查卡。** 展示诊断、病灶区域、知识点、审核人、版本和可用于的题型。 | 正式发布前检查病例是否具有适用于当前题型的金标准。模型输出只能作为专家制作答案时的预分析；未完成专家审核的病例不得用于正式考核。 |

| F7 | 发布与通知 | **图7：发布确认及学员通知。** 展示任务范围、截止时间、参与人和发布状态。 | 老师确认任务后，系统生成教学任务并通知学员。任务状态至少包括未开始、进行中、已提交、待老师复核、已完成和需重训。 |
| F8 | 学员进入数字阅片练习 | **图8：教学模式数字阅片器。** 展示数字切片、任务要求、答题区和隐藏答案状态。 | 学员在教学模式下调用数智化平台阅片器进行缩放、导航、标记、测量、病灶定位和圈定。练习期间隐藏正式诊断、专家标注及可能泄露答案的 AI 结果。 |
| F9 | 提交诊断过程与答案 | **图9：综合提交页面。** 展示病灶标记、诊断、鉴别诊断、IHC选择、报告和用时。 | 学员提交本次任务要求的结构化答案。系统保留首次答案、修改过程、最终答案和用时；正式考核时的可修改次数、提示和超时规则由任务配置决定。 |
| F10 | 执行客观评分 | **图10：评分结果页。** 展示选择题得分、定位命中、Dice、诊断符合度和报告字段完整度。 | 系统按照当前金标准版本和评分规则计算可客观评价的项目。诊断表述、鉴别思路和报告质量等需要专业判断的内容只生成评分建议，等待带教老师确认。 |
| F11 | 生成教学反馈 | **图11：答案对照与错误解释。** 展示学员结果、专家金标准、差异叠图、关键知识点和老师点评入口。 | Agent基于已确认金标准解释漏诊、误诊、圈定偏差和报告遗漏，并将事实差异与教学建议分开呈现。带教老师可以修改、补充或驳回反馈后再对学员可见。 |
| F12 | 推荐强化训练 | **图12：下一轮训练建议。** 展示薄弱点、推荐原因、病例难度和是否布置。 | Agent根据重复错误、病种覆盖和老师评价推荐下一批病例。推荐只形成草稿；老师可以一键布置、调整或不采用，避免系统把单次错误直接固化为长期能力结论。 |
| F13 | 支持病例讨论与读片会 | **图13：多人盲阅和分歧视图。** 展示每名学员的答案分布、共识、分歧和老师讲评顺序。 | 老师可以将同一病例发布给多名学员独立作答。提交截止后，系统汇总答案和标注差异，并生成讲评材料；正式诊断和专家答案由老师在讲评阶段揭示。 |
| F14 | 支持阶段考核 | **图14：阶段考核配置和结果。** 展示试卷蓝图、题型比例、病例覆盖、评分草稿和考官确认。 | 老师按部位、能力项和难度创建入科、阶段或出科考核。系统负责组卷、计时、客观评分和记录，考官确认综合成绩及是否通过，Agent不得自动给出人员资质或岗位授权结论。 |
| F15 | 教学进度与运营分析 | **图15：教师教学看板。** 展示完成率、病例覆盖、能力变化、逾期任务和重点干预学员。 | 老师、教学秘书和科主任按权限查看个人、培训组、部位和能力项表现。系统展示可追溯的事实数据，并将低完成率、重复错误和长期未进步者列入待关注清单。 |
| F16 | 教学病例和答案版本管理 | **图16：教学病例资产页。** 展示病例来源、脱敏状态、授权范围、金标准版本、审核记录和历史任务引用。 | 教学病例、诊断答案、病灶区域、题目和评分规则分别记录版本。答案更新后，历史训练继续保留原版本结果；新任务默认使用最新已批准版本。 |

## 5. 典型任务及跨平台联动

### 任务1：创建一次分部位专项训练

**典型请求**

> 给这批低年资医生安排一组胃肠病理专项训练，10个病例，由基础到进阶，一周内完成。

**任务流程**

1. Agent识别学员、部位、病例数、难度和截止时间。
2. 读取学员胃肠病理相关训练记录和病例覆盖。
3. 从教学病例库筛选已脱敏、已授权且具有专家金标准的病例。
4. 按基础形态、病灶定位、癌区圈定、诊断和报告分层组合。
5. 向老师展示病例及题型编排草稿。
6. 老师调整并确认。
7. 系统发布任务并通知学员。
8. 教师看板持续更新完成情况。

**需要注意的点**

- 不能因为学员没有历史记录就假定其能力水平。
- 同一训练包需要覆盖典型、易错和鉴别病例，不能只按模型置信度抽取。
- 正式发布前必须检查病例授权、脱敏和金标准状态。
- 训练难度由病例复杂度、可用信息、题型和提示共同决定，不能只由 Dice 阈值决定。

**与科研平台的可能联动点**

- 复用科研项目中的数据标签和病种标签辅助筛选病例。
- 引用已验收标注作为教学金标准候选。
- 调用研究模型进行病例预分析和难度辅助判断。
- 将教学中发现的高分歧病例提交为科研难例候选。

**与阅片平台的可能联动点**

- 从医院数据库、收藏夹和切片图书馆选择已授权病例。
- 调用病例信息、数字切片和关联切片。
- 复用数智化平台阅片器作为练习工作台。
- 复用已有专病 AI 结果制作教学答案草稿，但不直接向学员展示。

### 任务2：完成入科基线评估

**典型请求**

> 给刚进入病理科轮转的住培医生做一次入科摸底。

**任务流程**

1. 老师选择轮转阶段和预期能力范围。
2. Agent生成理论、图像识别、数字阅片和报告题的评估蓝图。
3. 从已审核病例中选择覆盖主要能力项的病例。
4. 老师确认题目、时限和评分规则。
5. 学员独立完成答题和阅片。
6. 系统完成客观评分，老师复核专业判断题。
7. Agent生成基线能力画像和建议训练重点。
8. 老师确认后形成该轮转周期的初始计划。

**需要注意的点**

- 基线评估用于制定计划，不直接代替医院正式入科考核。
- 题目需要覆盖多个能力维度，不能只用单一正确率概括能力。
- 职业素养、沟通和真实操作能力不能由线上测试替代。
- 能力画像必须展示依据和样本量。

**与科研平台的可能联动点**

- 使用经过审核的分类、检测和分割标注构建客观题。
- 使用模型评测中的难例丰富鉴别诊断题。

**与阅片平台的可能联动点**

- 调用教学模式阅片器完成真实WSI测试。
- 复用病灶定位、标记、测量和多切片对比工具。

### 任务3：完成一次日常数字阅片练习

**典型请求**

> 我今天想练5个乳腺病理病例。

**任务流程**

1. Agent确认学习者身份、目标、可用时间和期望难度。
2. 读取近期训练记录，避免重复推荐已熟练病例。
3. 推荐5个已授权病例并说明训练重点。
4. 学员逐例进入教学模式阅片器。
5. 学员完成病灶定位、初步诊断和必要的报告字段。
6. 系统记录提交内容、修改和用时。
7. 完成整组后展示总体结果和待加强知识点。

**需要注意的点**

- 学员练习过程中默认隐藏正式报告、AI结论和专家标注。
- 提示应分级提供，并记录提示使用情况。
- 推荐结果必须允许学员或老师更换病例。
- 不得从未经授权的临床病例中随机抽题。

**与科研平台的可能联动点**

- 使用数据标签、标注类型和难例标签辅助病例匹配。
- 将学员反复错误的区域转为待专家复核的难例标签。

**与阅片平台的可能联动点**

- 直接复用数字切片、关联切片和阅片工具。
- 调用相似病例检索提供训练后的对照病例。
- 在提交前隔离正式报告及临床生产 AI 结果。

### 任务4：完成癌区圈定实操题

**典型请求**

> 帮我布置一组前列腺癌癌区圈定练习，并按不同难度评分。

**任务流程**

1. 老师指定部位、病例范围、难度和圈定规则。
2. Agent筛选具有专家癌区标注的病例。
3. 老师确认金标准版本和是否允许查看提示。
4. 学员在数字切片上圈定癌区并提交。
5. 系统计算学员标注与专家标注的 Dice、漏标和过标区域。
6. 页面叠加展示差异区域。
7. Agent解释主要偏差并推荐相似练习。
8. 老师复核异常评分和特殊病例。

**需要注意的点**

- Dice只评价区域重叠，不等同于完整诊断能力。
- 小病灶、多灶、边界模糊病例需配置适合的评分规则。
- 专家之间存在标注差异时，应优先形成共识金标准或允许合理区间。
- 不能用单一Dice阈值定义所有病种和难度。

**与科研平台的可能联动点**

- 引用语义分割任务中已验收的专家标注。
- 使用两标一审结果构建更可靠的圈定金标准。
- 调用分割模型生成专家修订前的预标注。

**与阅片平台的可能联动点**

- 复用自由笔、区域编辑、缩放和导航工具。
- 调用专病 AI 病灶区域作为预分析结果。
- 将教学圈定与关联HE、IHC切片联动显示。

### 任务5：完成诊断、鉴别诊断和报告练习

**典型请求**

> 给进修医生做一组甲状腺病例，要求写诊断、鉴别诊断和结构化报告。

**任务流程**

1. Agent根据教学目标选择包含完整临床信息和辅助检查的病例。
2. 老师配置哪些信息初始可见、哪些信息分阶段揭示。
3. 学员先提交镜下所见和初步诊断。
4. 系统按任务规则逐步提供IHC、分子或临床信息。
5. 学员补充鉴别诊断、检查选择和最终报告。
6. 系统检查报告字段完整性及前后逻辑。
7. Agent生成与专家答案的差异说明。
8. 老师复核诊断思路和报告评价。

**需要注意的点**

- 诊断表述可能存在同义词和合理差异，不能只做字符串匹配。
- 辅助检查应按真实诊断路径揭示，避免答案泄露。
- 报告完整性评分与医学正确性评分需要分开。
- 教学报告不能进入临床正式报告和签发流程。

**与科研平台的可能联动点**

- 使用标签体系规范病种、分型和属性。
- 使用模型输出作为病灶和分类的预分析材料。

**与阅片平台的可能联动点**

- 复用结构化报告模板和报告审核能力。
- 调用HE、IHC、IF或其他关联切片对比。
- 调用病理知识问答解释鉴别诊断，但答案必须引用教学知识库。

### 任务6：生成错题复盘和强化训练

**典型请求**

> 总结我最近两周的错题，并给我安排下一轮训练。

**任务流程**

1. Agent汇总近两周已完成任务、错误、老师点评和提示使用情况。
2. 按病种、能力项和错误类型归类。
3. 区分偶发错误、重复错误和数据不足。
4. 生成错题复盘，展示原题、答案差异和知识点。
5. 从教学病例库推荐对照病例和递进病例。
6. 学员或老师确认后创建强化训练。
7. 完成训练后比较同类能力是否改善。

**需要注意的点**

- 一次错误不能直接定义长期薄弱能力。
- 错题解释必须基于专家答案和审核后的知识内容。
- 推荐不能只重复原病例，应包含相似和对照病例。
- 学员需要知道系统为什么推荐这些内容。

**与科研平台的可能联动点**

- 将高频错误区域和模型难例进行交叉分析。
- 将新发现的病例模式提交为标注或评测数据候选。

**与阅片平台的可能联动点**

- 调用以图搜图和病例检索寻找相似病例。
- 调取历史阅片标记和练习记录进行对照。

### 任务7：组织一次教学阅片会或病例讨论

**典型请求**

> 本周五组织一次肺病理读片会，先让大家盲阅，再集中讲评。

**任务流程**

1. 老师确定主题、参与人、病例数和讨论时间。
2. Agent筛选病例并生成盲阅任务草稿。
3. 老师确认病例、答案和信息揭示顺序。
4. 系统向参与者发布同一组独立作答任务。
5. 截止前隐藏其他人的答案和正式诊断。
6. 截止后汇总诊断、圈定和理由分布。
7. Agent生成共识点、主要分歧和建议讲评顺序。
8. 老师在读片会上揭示答案、点评并记录结论。
9. 系统保存讲评记录和病例教学版本。

**需要注意的点**

- 盲阅阶段必须避免参与者互相看到答案。
- 多数意见不等同于正确答案。
- 会议纪要和专家点评需要由老师确认。
- 病例讨论结果不能自动修改临床报告。

**与科研平台的可能联动点**

- 使用多人标注比较能力展示学员分歧。
- 将专家共识区域沉淀为新的标注版本。

**与阅片平台的可能联动点**

- 复用远程阅片和多切片对比能力。
- 从切片图书馆选择经典病例。
- 调用同屏展示支持老师讲评。

### 任务8：创建阶段或出科考核

**典型请求**

> 按这次胃肠轮转要求，给学员创建出科考核。

**任务流程**

1. 老师选择培养要求、能力项、题型、时限和通过规则。
2. Agent生成考核蓝图并检查病例覆盖和难度分布。
3. 从正式考核病例池抽取未被该学员练习过的病例。
4. 考官确认试卷、评分规则和异常处理方式。
5. 学员在受控环境中完成考试。
6. 系统生成客观评分和专业判断题评分建议。
7. 考官复核，填写操作能力及综合评价。
8. 系统形成考核记录，交由授权人员确认结果。

**需要注意的点**

- 练习题库和正式考核题库需要隔离。
- Agent不能自行设定医院的通过标准。
- 异常中断、超时、补考和题目争议必须留有处理流程。
- 线上结果不能自动替代住培办或考官的正式结论。

**与科研平台的可能联动点**

- 使用数据版本和标注版本保证考核可复现。
- 复用模型评测思想检查题目区分度和异常表现，但不能以模型结果代替专家答案。

**与阅片平台的可能联动点**

- 使用数字阅片器完成限时实操。
- 调取关联切片和结构化报告组件。
- 考试状态下关闭会泄露答案的 AI、相似病例和正式报告入口。

### 任务9：查看教学进度并干预重点学员

**典型请求**

> 帮我看看这批住培医生本月的完成情况，哪些人需要重点带教？

**任务流程**

1. Agent读取当前用户有权限查看的培训组和教学计划。
2. 汇总任务完成率、病例覆盖、错误类型、成绩变化和老师点评。
3. 按已配置规则识别逾期、重复错误或长期未改善情况。
4. 展示事实依据和数据量，不只给出风险标签。
5. 推荐老师可以采取的补课、病例练习或一对一反馈动作。
6. 老师选择是否创建干预任务。
7. 系统持续追踪干预后的变化。

**需要注意的点**

- 教学数据属于人员评价信息，必须按角色和培训组隔离。
- 排名不应作为默认展示，避免以单一分数替代综合评价。
- “需要关注”是教学提示，不是人事或资质结论。
- 数据不足、任务难度不同和缺勤需要单独说明。

**与科研平台的可能联动点**

- 复用任务中心和消息能力组织待办与提醒。
- 参考任务审计能力记录谁创建、修改和确认了评价。

**与阅片平台的可能联动点**

- 汇总教学模式下的阅片量、标记和用时。
- 临床生产阅片数据如需用于教学评价，必须另行授权并定义口径。

### 任务10：把一个临床或科研病例沉淀为教学病例

**典型请求**

> 把这个典型病例整理成乳腺病理教学病例。

**任务流程**

1. 老师从数智化平台病例或科研数据集中发起“创建教学病例”。
2. 系统检查数据来源、教学授权和脱敏状态。
3. Agent汇总切片、临床资料、辅助检查和既有标注。
4. 模型可生成病灶预分析、候选知识点和题型草稿。
5. 病理专家修订诊断、病灶区域、鉴别点和讲解内容。
6. 第二位专家或教学负责人按规则审核。
7. 系统形成带版本号的教学金标准。
8. 老师配置适用人群、部位、病种、难度和可用题型。
9. 病例进入教学病例库，供后续训练和考核引用。

**需要注意的点**

- 临床病例进入教学库前必须完成授权和脱敏。
- 模型分析只能作为制作答案的辅助材料。
- 临床报告修订不应自动覆盖教学金标准，反之亦然。
- 病例、切片、标注、答案和评分规则需要分别记录版本及引用关系。

**与科研平台的可能联动点**

- 引用已验收标注数据集和标注模板。
- 调用两标一审建立专家区域共识。
- 调用模型评测结果筛选典型正确病例和难例。
- 将教学专家修订反馈沉淀为新的科研数据候选，而不是自动回写训练集。

**与阅片平台的可能联动点**

- 从收藏夹、切片图书馆、医院数据库和会诊病例中选择候选病例。
- 读取数字切片、关联切片、AI结果和医生修订记录。
- 使用教学副本隔离临床报告和教学答案。
- 保留病例来源和临床版本的可追溯关系。

## 6. 三个平台的能力边界

| 平台 | 在教学链路中的主要职责 | 不承担的职责 |
|---|---|---|
| 病理教学平台 | 管理学员、教学任务、题目、金标准、练习、评分、反馈和教学分析 | 不生产临床正式报告，不直接训练模型 |
| 病理数智化平台 | 提供病例、数字切片、关联切片、阅片器、专病AI、病例库和报告组件 | 不自动把临床病例授权为教学数据，不替代老师确定教学答案 |
| 病理科研平台 | 提供数据集、标签、标注、审核、模型、评测和难例分析能力 | 不自动把教学结果写入训练数据，不承担正式教学评价 |

跨平台联动统一遵循：

- **病例流转：** 临床或科研病例先形成受控的教学副本，再进入教学病例库。
- **模型调用：** 模型是预分析和辅助评分工具，不是教学答案责任主体。
- **人工确认：** 教学病例、金标准、主观评分和考核结果分别由有权限的病理专家或考官确认。
- **版本追踪：** 病例、切片、标注、模型、答案、题目和评分规则均保留版本及引用关系。
- **权限隔离：** 临床、科研、教学三类用途分别授权；能够临床阅片不自动意味着可以制作或参加教学。
